提醒开关

          
          
关闭总开关后，下面四项全部停止；已注册的 Windows 计划任务也会一并注销。
            提醒任务本身不会删除，重新打开后按原计划继续。

          
          
          
          
          
定时提醒（新提醒进入工作台）

          
系统通知：检查中…

          
          
          
          
          
          
          
          

          
新提醒会直接进入工作台「日程」（到点弹 Windows 系统通知，即使本程序已关闭，由系统计划任务负责），并在会话里留一条消息。也可以在工作台用快速添加（如「明天 10 点 开会」）或「＋ 日程」创建；点已有日程可改时间 / 地点 / 重复规则与提醒。这里保留未迁移/停用的旧提醒与主动聊天。


          
主动聊天

          
开启后 AI 会隔一段时间主动找你说话（仅在程序运行时；连续 2 次没得到回应会自动暂停）。开启后约 20 秒会先发一条，让你立刻看到效果，之后才按下面的间隔。

          
          
          
          
          
          
改完间隔立刻生效，不用关掉再开。

          
          

        

        

          
图片生成（本地 ComfyUI）

          
          
          
          
          
          

            
            
          

          
模型建议：FLUX 3 Image Klein 蒸馏版（INT8 / NVFP4）+ Qwen3-VL-4B 编码器 + FLUX.2 VAE。
            在 ComfyUI 里打开官方模板后用「另存为 API 格式」导出到上面的路径；正向提示词里保留
            __PROMPT__ 占位符，生成时会替换成你输入的描述。固定 16 步，尺寸只给三档。

        

        

          
全局规则

          

          
          
每条规则可以单独启用 / 停用；启用的规则按列表顺序拼接，对每个对话都生效。建议写法：角色与目标 / 判定标准 / 每轮必做 / 禁止。


          
自动记录

          
          
AI 会在对话中自主增删改偏好，写入「用户画像」知识库，可在知识图谱中查看与编辑；每条偏好即一个节点。写入后回复下方有「已更新记忆」标记，可撤销。判断准则可在下方「学习指令」中自定义。

子代理团队

          
每个代理是一个 Markdown 文件（data/agents/<id>.md）：frontmatter 写
            name / description / tools / model / max_turns / permission，正文是系统提示词。
            默认只读；勾选「允许写文件」后可用 write_file / edit_file，每次写仍走审批与撤销。
            保存后下一轮对话生效。主代理可用 delegate 派活，或用 pipeline 串行交接。

          

            
            
          

          
自动派发

          
          

            系统提示会列出上面启用的代理与派活时机；连续多次只读还没派活时，提醒一次。
            只影响「要不要派活」的判断，不替你执行任何操作。
          

          
          

            只对像「要动手」的任务触发（单文件小改、纯问答不跑），计划会注入本轮上下文，
            由主代理用 update_plan 落成计划卡。planner 只读，不改文件。
          

          
          

            本轮确实写过文件才触发，结论会回灌给主代理；更慢也更贵，默认关闭。
          

          
          

            默认开启：出现第一份计划时先弹审批卡，可以批准、提意见或逐条改步骤。
            `/plan` 规划模式始终生效，不受这个开关影响；关闭后普通任务会直接开始执行。
          

          
脚本编排

          
          

            脚本化工作流里可以按名字派活；写权限跟随代理定义，implementer / documenter
            的每次写入仍走审批。关掉后脚本只能调工具与 DAG 工作流。
          

          
          
          
并行写隔离

          
          
          

            所有写入本来就会串行执行；这里管的是「两个代理先后改同一文件」：
            提醒模式只把「刚由谁改过」回灌给子代理，严格模式直接拒绝第二次写。
          

          
          
          

            同一批多个可写子代理各拿一份本地 git worktree（data/worktrees/），
            各自改各自的副本，互不覆盖；跑完产出补丁，经审批后回写主沙箱，
            并登记一条可撤销记录。沙箱不是 git 仓库时自动退回上面的「串行写 + 冲突提示」。

            对任务领域没有假设。模型可以在 finish 里用 quality_waiver 写明为什么不再迭代。

主题

          

            
            
            
            
            
            
          

          
切换界面明暗；应用窗口的标题栏也会跟随。GAL 演出主题（樱粉 / 夜蓝 / 和风纸 / 极简黑白 / 霓虹夜景 / 像素复古）在「GAL 演出」里单独设置，进入 GAL 模式时它会覆盖配色。详见「功能说明 → 主题与外观」。


          
对话过程

          
          
开启后，过程折叠区里每出现一个新步骤会自动带进视野，但不强行拉到整条消息底部；你往上翻立即暂停，回到底部或点右下「回到底部」恢复。关闭后只更新「N 步」统计，不再自动滚动（当前步骤高亮与已完成步骤的自动收起仍然生效）。


          
IDE 编辑器主题

          
          

            
            
            
            
            
            
            
            
            
          

          
只在 IDE 模式生效，退出 IDE 立刻恢复界面主题；与上方「主题」各存各的，互不干扰。VSCode Dark Modern / Light Modern 是 VS Code 现在的出厂默认主题（Dark+ / Light+ 是更早的「传统」默认）。跟随 VS Code 会读取本机 settings.json 里的 workbench.colorTheme 并在约 5 秒内跟随切换：官方内置主题直接套用上面的预设，第三方主题则按其配色映射（映射是有损的，缺项会回落到界面主题）；语法高亮不跟随，仍用与明暗匹配的 Dark+ / Light+。


          
空白字符

          
          
开启后空格渲染为浅灰中点 ·、制表符渲染为 →，颜色沿用 VS Code 的标准值（深色 #e3e4e229 / 浅色 #33333333），不随主题改写，观感与原生编辑器一致。

选项

          
          
选项浮在画面中部，可用鼠标点、↑/↓ 移动后 Enter 确认，或直接按数字键 1–9。

语音输入

          
          
          
AI 矫正：识别出的文字会先交给「聊天模型」做最小必要的校对（补标点、纠错别字、去口癖），再填入输入框；可在输入框下方点「撤回原文」恢复未矫正的文本。降噪：先在本机对音频做流式去背景噪声（DPDFNet）再识别，需先运行 scripts/fetch_speech_model.py denoise 下载模型。实时转写 / 两遍精修无需在此配置。详见「功能说明 → 语音输入」。

改键

          
点条目右侧「改键」→ 按下新键即可（Esc 取消）。改动即时生效并保存在本机；与同一分组内已有键冲突会被拒绝，与其它分组撞键则允许并提示 —— 按「用户自定义优先」，你改过的那条会压过对方的默认键。可以用「解除」取消某条绑定，用「重置」恢复单条默认，分组标题右侧可「恢复本组」，底部可「全部恢复默认」。灰显表示当前模式下不可用；面板内的导航键（↑↓ / Tab / Enter / Esc）属于控件标准交互，不开放修改。

对话行为


        

          深度思考：开关、档位与参数模式
          

            
开关（输入框左下「深度思考」）：开启后模型在给答案前先输出一段思维链（CoT），回答通常更准，但更慢、更费 token。思维链会以可折叠的「已深度思考」块展示。

            
档位（点「深度思考」右侧的小箭头选低 / 中 / 高 / 最高）：控制"想多久"。本程序按「思考参数模式」把它作为 reasoning_effort 发送。DeepSeek 官方会对档位做映射（依其官方文档）：

            

              
本程序档位发送值DeepSeek 实际生效

              
低lowlow

              
中mediumhigh

              
高highhigh

              
最高maxmax

            

            
参数模式（设置 → 模型接入 → 推理参数）决定上述开关如何传给接口，避免不支持的接口报错：

            
    
              
  • 自动：按接口地址是否含 deepseek 自动判断。
    • 
              
  • 不发送：完全不带思考参数，最通用。
    • 
              
  • OpenAI 兼容：开启时发 reasoning_effort，关闭时不发（无法表达"禁用"）。
    • 
              
  • DeepSeek：开启→ thinking.type=enabled，关闭→ disabled；档位走 reasoning_effort。
    • 
            

            
注意：在 DeepSeek 上「中」与「高」效果相同（都映射为 high），真正有区别的是「低 / 高 / 最高」。其它厂商对 reasoning_effort 的支持与映射可能不同，甚至不支持（会被忽略或报错）。

            
另：思考模式下 DeepSeek 会忽略 temperature / top_p 等采样参数（不报错但不生效）。

          

        


        

          上下文上限（回复末尾的圆环）
          

            
估算当前会话离模型上下文上限还有多远，避免"聊到一半突然报错"。相关设置项在「上下文与压缩」。

            
    
              
  • 两个数字是什么：模型上下文窗口是模型一次能装的 token 总量（输入 + 输出都算）；留给 AI 回答是从窗口里先划给本次回答的空间，聊天历史最多用到「窗口 − 预留」。预留不是 max_tokens，不会硬性截断回答，只会让压缩更早发生。
    • 
              
  • 窗口填 0 = 不限：不猜模型窗口、不显示圆环、不按窗口触发压缩，也不按窗口夹输出上限；只保留请求体大小的实现层兜底。
    • 
              
  • 怎么看：最新一条回复的右下角有一个小圆环，右侧是占用百分比，环的颜色随剩余量转黄 / 红。
    • 
              
  • 点圆环：直接执行「压缩历史」——把较早的对话总结成摘要，确认后才会执行；原文不会被删除。
    • 
              
  • 点百分比：打开「上下文与压缩」详情，可看各分项占用与摘要全文，或「恢复原文」撤销压缩。
    • 
              
  • 「token 明细」页签：同一弹窗的第二个页签——逐轮列出每次调用的输入 / 输出 / 状态 / 首包耗时与「输入构成」（规则 / 记忆 / 工具结果 / 历史各占多少）；上方还有总输入、缓存命中、末轮输入、平均每轮输入与推理输出。
    • 
              
  • 单位换算（按本项目的估算口径）：1 个汉字 / 中文标点 ≈ 0.6 token，1 个英文字符 ≈ 0.3 token。即 1000 token ≈ 1700 汉字；128000 token ≈ 21 万汉字；1000000 token ≈ 170 万汉字。填写时只写数字：128K 写 128000，1M 写 1000000。
    • 
              
  • 已用 ≈ 本地估算 × 校准系数；校准系数取最近一次接口返回的真实 prompt_tokens ÷ 当时估算。估算范围包含系统提示、摘要、对话正文、附件正文与图片描述。
    • 
              
  • 剩余 = 上限 − 已用；剩余低于上限 10% / 5% 时圆环转黄 / 红并弹出提醒。
    • 
              
  • 预压缩（可用提示词预算）：已用达到 min(窗口的 80%，窗口 − 输出上限 − 8192) 时，后台开始把较早的对话总结成摘要；本轮请求不等待，下一轮自动生效。
    • 
              
  • 兜底压缩（已用 + 预留超窗口）：发送前「已用 + 预留」仍超窗口时，会同步再压一次；若压缩失败，本轮只临时省略较早消息再发送，本地原文不会被删除。
    • 
              
  • 保留哪些：默认保留最近约 16% 输入窗口（窗口 − 输出上限）的原文（至少 8 条，最多 60 条），更早的进入摘要；新摘要会合并旧摘要，保留未完成事项与用户明确指令。
    • 
              
  • 常态控制（省费模式）：开启省费模式后，每轮还会按「历史原文预算」（默认 40000 tokens）压一次回合起点，超出部分进结构化摘要；当前回合的原文永远保留（切点不会越过最后一条真正的用户消息）。窗口阈值（80%）是超限救火，这一层是每轮生效的常态控制，详见下一条。
    • 
              
  • 摘要用哪个模型：走「轻量模型」（设置 → 聊天 API 里的小模型配置）；未配置时自动沿用主模型。
    • 
              
  • 压缩前写记忆：生成摘要时会附带最多 6 条「记忆要点」，写入本会话记忆，避免摘要失真后彻底失忆。
    • 
              
  • 窗口 / 预留可在「上下文与压缩」里按所用模型填写。出厂默认 100000000 / 16384，即等效「足够大」，不会按窗口比例触发压缩；想启用按比例的预压缩，就把它改成模型的真实窗口（例如 128000）。填写框下方会实时算出可用提示词预算与压缩触发点；估算为近似值，仅供参考。
    • 
            

          

        


        

          省费模式：历史预算 / 引用句柄 / 提示缓存
          

            
设置 →「上下文与压缩 → 省费模式」。它只改变发给模型的历史，本地原文一条都不删。

            
    
              
  • 省费模式（默认开启）：@文件 / @目录 的正文只在当轮内联；更早轮次只留「路径:行号」句柄，需要时模型用 read_file 按需取回。界面状态、意图、自动化目标改贴到请求末尾，避免整段历史每轮失去前缀缓存。关闭后回到旧行为（quality，装配结果与旧版一致）。
    • 
              
  • 历史原文预算（默认 40000 tokens）：每轮最多重发多少历史原文，超出部分压进结构化摘要；当前回合始终保留原文。调大更保守也更费钱；调小更省，但更依赖模型按需重读文件。
    • 
              
  • 单回合输入预算（默认 3000 万 tokens）：一个回合累计输入超过它就先收尾，并保留「继续任务」，只拦病态长跑。
    • 
              
  • 历史附图保留条数（默认 2）：把最近几条带图消息重新作为图片附上（每条最多 2 张）。设为 0 时历史里只留「可回看附件」一行，模型可能要求你重新发图。
    • 
              
  • Anthropic 提示缓存（默认开启）：在稳定段与历史前缀各打一个 cache_control 断点，命中约按 0.1 倍计费、写入约 1.25 倍；OpenAI 兼容通道不受影响。
    • 
              
  • 怎么看效果：上下文弹窗的「token 明细」里有「单次调用 P50」与「前缀复用」两张卡；前缀复用越低，说明 system / 历史越不稳定，缓存越容易失效。
    • 
            

          

        


        

          联网搜索（判据 / 抓取 / 来源）
          

            
输入框的「联网搜索」开关开启后，会把这个能力交给模型：模型自己判断这一轮要不要查——需要时它给出关键词式检索式，程序并行搜索、抓取正文、把资料回灌给它，然后它再据此作答（回答上方会出现可折叠的「参考来源」列表）。不需要时它就不查，不会无谓地多搜一轮。

            
    
              
  • 服务商 / 密钥：默认「自动（免注册引擎链）」——Firecrawl → Keenable → You.com 依次尝试，都不需要注册或密钥，额度耗尽的引擎会冷却一段时间后自动跳过；也可改选博查 / 豆包搜索 / Tavily 并填密钥。接口地址留空则用该服务商的默认地址。顶部的「启用 modsearch」是总开关，关掉后不调用任何免注册引擎、也不会把网页发给 Firecrawl 云端抓取。
    • 
              
  • 谁来改写检索式：由模型在调用搜索时自己给 1–3 个关键词（口语化的「它 / 这个」它会自己补成具体名字），不再额外单独判断一次。
    • 
              
  • 抓取正文：对命中的网页取正文（而不是只有摘要），信息密度更高；可设抓取条数。默认先用云端浏览器（Firecrawl，能读 JS 渲染的页面），失败回落 Jina Reader（免密钥）→ 直连抓取，再失败则保留摘要。云端抓取会把目标 URL 发给 Firecrawl，私网地址始终走本地。
    • 
              
  • 结果条数：每个检索式各取多少条。
    • 
              
  • 注入不入库：抓到的正文只用于本轮提示，不会写进会话文件。

          知识库与记忆（侧栏「知识库」）
          

            
    
              
  • 本会话记忆：只属于当前对话，切到别的对话就看不到。
    • 
              
  • 通用知识库：可有多个、跨对话共享；在编辑器右侧勾选哪些库给"本会话"用（可多选）。
    • 
              
  • 用户画像库：系统库（AI 自主写入），每轮固定注入，不允许删除 / 改名。
    • 
              
  • AI 可否修改：分两级——会话级「允许 AI 写本会话记忆」与库级「允许 AI 修改本库」；被锁定的节点 AI 不会改。
    • 
              
  • 检索方式：标题 / 别名权重最高，其次标签、分类、正文；再用 IDF 压低「的 / 我」这类无区分度的词，并做长度归一化，避免内容多的节点仅凭字数霸榜。候选超过 40 条且分数没有明显断层时，才让模型做一次挑选。
    • 
              
  • 查询扩展：你只说「继续 / 这个」这类短句时，会自动拼上一轮的话一起检索。
    • 
              
  • 关联扩展：命中的节点会额外带上一跳邻居（最多 4 条，标注关系），关系图谱里的边不再只是摆设。
    • 
              
  • 别名：节点可填别名 / 简称（最多 8 个），检索和「AI 找条目」都会匹配；合并节点时原标题会自动变成别名。
    • 
              
  • 关联面板：选中节点后，「关联」区列出入边 / 出边和「提及但未连线」的节点，点击可跳转。
    • 
              
  • 检索测试：右栏「检索测试」输入一句话，可看到本轮会注入哪些条目、分数、来源、是否邻居，以及是否触发了模型挑选。
    • 
              
  • 批量操作：按住 Ctrl 点选多个节点后，可移入主题、批量加标签、合并（保留第一个）、批量删除。
    • 
              
  • 导出：右上角「⋯」可导出 Markdown / JSON，或把当前图谱导出为 PNG。
    • 
              
  • 图谱编辑：拖拽移动、双击空白新增、「节点」按钮新增、点节点改内容、连线 / 删边（画布左上角工具栏）、删除节点；节点可调大小与颜色（AI 也能设，用于区分重要度 / 分组）。
    • 
              
  • 图谱力学：右侧「图谱设置」可调斥力 / 中心引力 / 弹簧强度 / 线段长度，拖动即时生效，设置随该知识库保存。

          图谱关系类型（箭头代表什么）
          

            
知识库的边分单向和双向两种：
              单向箭头从 A 指向 B，读作「A 关系 B」（如因果、条件这类有先后的）；
              双向两端都有箭头，表示互相（如相关、同义、对立这类 symmetric 关系默认画双向）。
              关系取自下面的固定词表（标注「⇄ 默认双向」的即为对称关系），图上按类型着色；AI 也只能从词表里选（写别的说法会自动归一到最近的类型）。

            
    
            
    你可以点节点后用「连线」按钮手动建立关系，并在表单里选择「单向 →」或「双向 ⇄」；AI 整理记忆时若发现两个已有条目之间存在明确关系，也会主动连边（方向按关系类型自动判断，也可由 AI 显式指定）。

          Agent 沙箱（文件读写与命令）与审批
          
    
            
      
              
    • 开启：点输入框下方的「Agent」开启，再点「目录」选择沙箱目录；设置按会话保存。
      • 
              
    • 能力：模型可在沙箱内 列目录 / 读文件 / 搜索 / 写文件 / 改文件 / 建目录 / 移动 / 删除，并能执行命令（python / node / npm / git / pytest 等白名单程序），拿到退出码与输出。
      • 
              
    • 命令限制：默认只支持前台命令，不支持管道、重定向与后台常驻进程；白名单外的程序（cmd / powershell / curl 等）一律拒绝；python / node 只能执行沙箱内的 .py / .js，-c / -e 内联代码一律拒绝，-m 只放行 pytest / pip 等固定模块。以上限制在完全访问档全部解除（仍限在沙箱目录内执行）。它不是系统级沙箱——沙箱内的脚本本身仍可再起子进程，这一层靠审批档位兜底，不是操作系统级隔离。
      • 
              
    • 审批四档：手动审批每次写入 / 命令前都问；自动审批按风险放行——新建文件、建目录、普通编辑、只读命令、跑测试与脚本直接执行，删除 / 移动 / 语义重命名、覆盖已有文件、安装 / 联网 / 破坏性 Git（push、reset、clean）才问；完全访问不询问、不校验命令白名单，允许内联执行与管道 / 重定向，Git 提交与站点授权也不再确认（仍限在沙箱内，银行 / 支付 / 邮箱等站点除外）；自定义只看沙箱内 .gm/agent-rules.json。
      • 
              
    • 安全：只接受沙箱内相对路径，越界、绝对路径直接拒绝；.git / .venv / node_modules / __pycache__ 与本项目 data/ 永久禁止访问。
      • 
              
    • 写后自检：写完会立刻做一次语法 / 结构检查，有错直接把报错回灌给模型让它自己修（成功时不额外占 token）。
      • 
              
    • 画面自检（render_check）：写完网页 / 小游戏 / UI，模型可以用无头浏览器真的打开这个 HTML，拿回运行时错误、零尺寸画布、元素遮挡、字号过小、对比度不足、点击区过小等结论；需要判断配色观感时可加 screenshot，由视觉模型描述画面（优先聊天模型，不支持图片时自动换视觉 API）。只接受沙箱内的 .html / .htm，不联网。手感、动效仍需你自己看。
      • 
              
    • 声音自检（audio_probe）：写完音效 / BGM 后，模型可以真的读一遍音频（WAV / FLAC / OGG / MP3），拿回响度包络、起音、RT60 混响、频谱质心、事件密度等可复算的测量值，以及「冲击 / 压迫 / 空间 / 清晰」四个代理分数；改前改后用 audio_compare 对比（会先抵消整体响度差，避免「只是变响」被当成变好）。它听不出好不好听——那一步仍需你的耳朵。
      • 
              
    • 改动可撤回：每次写操作生成一张工具卡片，点卡片上的「撤回」即可恢复该次改动。
      • 
              
    • 读沙箱外：输入框的「沙箱外」开关（仅 Agent 开启时显示）可让 AI 在你明确要求时读取沙箱外的文件——只读，写入仍只在沙箱内。
      • 
              
    • 中途提问：需要你决策时，AI 会在对话里弹出一张提问卡（可点选项或自己输入），你回答后它会原地继续，不用重新发消息。提问与 Agent 无关，不选沙箱也能用。
      • 
              
    • 相关设置：轮次、重复拦截、自动续跑次数、命令超时在「设置 → Agent 执行」；自动化的提问策略、重启恢复、看门狗在「设置 → Agent → 自动化（Autopilot）」。

          执行计划与分步思考（过程里的「步骤 2/5」）
          
    
            
    开了 Agent 之后，长任务会先列一份执行计划再一步步做。对话里的过程按时间线排：每一步先出现一个可折叠的「步骤 N · 思考中…」，下面是这一步的工具调用，做完自动折起。
    
            
      
              
    • 「步骤 2/5」是什么：斜杠前是当前第几步，后面是计划总步数。计划由模型用 update_plan 自己维护，做完一步更新一次；工具组的标题也会显示这一步的计划文字。
      • 
              
    • 为什么中间会停一下：每一步动手前它先判断「上一步的结果说明什么、接下来做什么」。这段判断会压成一小段摘要带回下一轮，让它不用重复读同一个文件。
      • 
              
    • 上一步摘要在哪看：不单独展示，只作为内部提示；界面上折叠的思考块是模型这一轮真实输出的思维链（要先开「深度思考」）。
      • 
              
    • 计划会改：计划是活文档。大型任务会按里程碑（M1 / M2…）分组，每步带验收方式；中途发现新事实、某步失败或里程碑完成时，模型用 plan_patch 改受影响的那几步，卡片标题会显示版本号（v2、v3…），展开底部「变更记录」能看到为什么改。
      • 
              
    • 先规划再动手：在输入框发 /plan 你的目标，这一轮会进入只读规划模式——只读文件 / 搜索 / 提问，先产出「目标 + 完成判据 + 里程碑」，等你确认后再执行。
      • 
              
    • blocked 是什么意思：某一步做不了（缺权限、等你决定）时，模型会标成 blocked 而不是死磕。标了 blocked 的步骤算「已处理」，不会再触发自动续跑。
      • 
              
    • 失败诊断：工具报错时会附带「这类错误通常怎么解 / 不要用完全相同的参数重试」的提示，避免它一条道走到黑。
      • 
              
    • 预算提示：轮次快用完（还剩 3 轮）时会提醒它优先收尾，并把没做完的部分明确告诉你。
      • 
            
    
          
    
        
    

        
    
          自动化：自主规划到完成、断了自己续、提问按策略处理
          
    
            
    在输入框写目标，点「自动化」。它不会只做一轮：先立项（完成定义 + 粗计划），再自己执行、机检、独立评审，直到验收全部通过或需要你介入。
    
            
      
              
    • 完成判定：能跑命令就跑命令（构建 / 测试 / lint / 启动检查 / HTTP 探活）；没有可机检项时，由新上下文的独立评审员只看证据判分。判定不了的项不算通过，不会靠「我觉得做完了」收工。
      • 
              
    • 不会交半成品：计划与验收全过才算完成；长时间没有实际进展或预算耗尽时转「需要你」，不会把半成品标成完成。
      • 
              
    • 断点续跑：网络 / 超时 / 空回合会自动退避重试；进程重启后会把未完成目标接回来。断点里包含上次改过的文件、上次验收，以及「执行到一半结果未知」的工具，续跑会先核对现状再动手。
      • 
              
    • 提问策略：设置 → Agent → 自动化里三档——auto 一律自决；smart 可逆自决、删除 / 覆盖 / 发布 / 付款 / 改凭据 / 缺外部信息时暂停问你；ask 一律问。自动化里不弹交互卡，问题会写进正文和目标，回答后点「自动化」恢复。
      • 
              
    • 状态与恢复：按钮显示「运行中 / 重试中 / 需要你 / 已暂停」；点「需要你 / 已暂停」会恢复原目标，不会拿输入框新建一个。
      • 
              
    • 无进展看门狗：连续多回合没有新的写入 / 验收变化会强制重规划，仍无进展就暂停等你。默认不设固定回合上限；需要严格控制成本时，在设置里打开「硬上限」。

          自动续跑：什么时候自己继续、什么时候会停
          
    
            
    这一节是普通对话的自动续跑；目标级自动化（立项 / 验收 / 断点续跑）见上一条。
    
            
    模型有时会在其实没做完的时候收尾，等你再说一遍「继续」。自动续跑就是省掉这一步：它想收尾时先检查一遍，没做完就自己推它往下做，过程流里留一条「自动续跑 1/3」的浅提示，你能看出不是卡住了。
    
            
      
              
    • 三种触发：① 计划里还有没做完的步骤；② 没有计划，但结尾在问「要不要 / 需要我」；③ 是开发型任务、既没建计划也没动手，催一次让它先列计划。
      • 
              
    • 什么时候放行：计划全部完成（含 blocked），或它明确说了「已完成 / 改完了」，就直接结束，不会硬拖。
      • 
              
    • 显式收尾：模型可以调用 finish 声明本轮完成（可带摘要与未完成说明）；计划里还有未完成的步骤时，这个声明不会被采纳，会继续跑。
      • 
              
    • 次数上限：默认 3 次，可在工具条的 Agent 菜单或「设置 → Agent 执行」里改成关闭 / 3 / 5。到上限就正常停下，等你决定。
      • 
              
    • 为什么不再问「要不要继续」：提问通道收紧了——实现细节、命名、先改哪个文件都由它自己定；真要你决策时会弹「提问卡」，而不是在正文里问一句然后停下。
      • 
            
    
          
    
        
    

        
    
          多会话并行：切走不中断，可以同时跑两条
          
    
            
    以前切换会话会直接停止当前生成。现在切走只是「把这轮放到后台继续跑」：你可以去另一个会话里发新消息，两边同时生成、互不打断。
    
            
      
              
    • 会话列表的小圆点：蓝色闪动 = 正在生成；黄色常亮 = 在后台生成完了，还没切回去看。

      •

      •

          工作台总览（日程 / 任务 / 产物）

    • 日程：今天或未来 7 天的安排；点任意一条即可编辑，右上角「＋」新建。
      • 
              
    • 任务：可拆步骤、可暂停恢复的执行单元；点卡片看详情。
      • 
              
    • 产物：任务写出的文件，按任务分组。
      • 
              
    • 刷新：日程与产物的变更会实时推送；任务进度本来就是实时的。断线时最多 30 秒也会自动补齐。

          任务：写操作确认 / 断点恢复 / 重试 / 改计划
          
    
            
      
              
    • 写操作确认：任务里涉及写文件、建 / 改日程等写操作的步骤，第一次会停在「待确认」；打开任务详情点「确认执行」才继续。读操作（列目录、查日程、搜索）直接跑。
      • 
              
    • 断点恢复：状态实时落盘。进程重启后，原本在跑的任务统一转为「已暂停」，不会自动重跑，避免同一个写操作执行两次。
      • 
              
    • 失败重试：任务失败后点「重试失败步骤」——只把失败的步骤退回待执行（已完成的步骤不重跑），并显示已重试次数。
      • 
              
    • 改计划：任务处于「待开始 / 已暂停 / 失败」时，可以增删步骤、改标题、调整顺序、给步骤绑定能力或填参数。已完成的步骤不会被动；换了能力或改了参数会重新要求确认写操作。
      • 
              
    • 手动步骤：没有绑定能力的步骤由你自己完成，点「标记完成」推进。
      • 
              
    • 优先级与标签：新建或「编辑信息」里设置，P1–P3 会显示在卡片上；任务列可按状态筛选、按标题 / 标签搜索。
      • 
              
    • 截止时间：新建任务时填「截止时间」会同步一条截止日程并提前提醒；取消 / 完成任务会自动关掉这条日程。

          产物：交付物 vs 临时文件
          
    
            
      
              
    • 什么算产物：只有真正写出文件的步骤（写文件 / 改文件 / 移动文件）会登记；删除文件、建目录不算。
      • 
              
    • 交付物 / 临时文件：写在 tmp / temp / cache / __pycache__ / .git / node_modules / build / dist 等目录下，或文件名以 . 开头的，归为「临时文件」；默认只显示交付物，点列头「交付物 / 全部」切换。
      • 
              
    • 分组：按所属任务分组显示，组头就是任务标题；同一任务重复写同一个文件只保留一条，并更新大小。
      • 
              
    • 预览：文本、图片直接看；Markdown 会渲染，CSV 显示成表格；超过 256KB 只显示前 256KB。
      • 
              
    • 定位 / 移除：「定位」在资源管理器里打开所在文件夹；「✕」只从产物栏移除记录，不会删除磁盘文件。删除任务会一并清掉它的产物登记。
