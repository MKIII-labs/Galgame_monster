## 目标

让后来的人从说明里看懂动机和影响，而不是只看改了哪些行。

## 何时用

- 准备提交、开 PR、写发布说明

## 步骤

1. 先读 diff，按「行为变化」分组，不按文件分组
2. 每组写一句动机：解决什么问题，或避免什么风险
3. 标题写结果，不写过程（「修复登录态丢失」而不是「改 auth.py」）
4. 正文补齐：影响范围、验证方式、回滚方式
5. 无关改动拆出去，不混在同一次提交

## 输出

- commit：一行标题 + 2–4 行正文
- PR：改了什么 / 为什么 / 怎么验证 / 风险

## 禁止

- 用「更新代码」「修复 bug」当标题
- 把文件清单当说明
- 声称验证过，却没写验证方式
