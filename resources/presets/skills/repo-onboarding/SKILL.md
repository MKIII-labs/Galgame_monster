# 陌生仓库上手

用最少的阅读建立可用的心智模型，避免上来就猜。

## 何时用

- 第一次接触一个仓库或模块
- 用户问「这个项目怎么跑」「该改哪里」
- 需要判断某个改动应该落在哪一层

## 核心步骤

1. 看骨架：目录结构、构建与运行入口、依赖清单
2. 找入口：程序启动点、路由注册、主循环
3. 追一条主线：从用户操作到数据落库，只追一条，不要全看
4. 找测试：怎么跑、覆盖了哪些行为
5. 写一张 5–10 行的结构图（模块 → 职责 → 依赖）
6. 再定位改动点，并说明为什么是这里

## 输出格式

- 启动方式 / 关键目录 / 一条主线的调用链
- 建议改动点 + 风险

## 常见错误

- 没跑起来就给改造方案
- 一次读几十个文件却不给结论
- 把目录名当职责
- 只看代码不看构建 / 配置
