# 根因定位：二分与取证

## 先固定现象

- 记录：输入、环境（版本 / 平台）、频率、完整报错、最近改动
- 无法复现时，先补观测点（日志 / 指标 / 断言），不要开始改代码

## 二分法（每步排除一半）

| 维度 | 怎么切 | 观察什么 |
| --- | --- | --- |
| 最近改动 | 回退到上一个已知正常版本 | 现象是否消失 |
| 输入 | 最小化输入，逐步删字段 | 从哪一步开始出错 |
| 环境 | 换机器 / 换版本 / 关扩展 | 是否与配置相关 |
| 并发 | 单线程复跑 | 是否只在并发下出错 |
| 外部依赖 | 打桩 / 断网 / 本地 mock | 是否依赖返回值或超时 |

## 假设→证据

每个候选原因写成：

```
假设：<原因>
如果成立：<可观察现象>
验证：<命令 / 用例 / 日志行>
结论：成立 / 不成立 / 还缺证据
```

## 常见陷阱

- 相关性当因果：时间上同时发生不等于导致
- 观测偏差：加日志改变了时序，问题消失
- 幸存者偏差：只看了成功的样本
- 修表象：把异常 try/except 掉，根因仍在
