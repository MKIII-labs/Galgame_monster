## 目标

用最少的证据定位根因，而不是换一种写法碰运气。

## 何时用

- 现象可复现，但原因不明
- 改过一轮还没好，或时好时坏
- 日志 / 堆栈里有信息，但不确定关键点

## 步骤

1. **复现**：确认触发条件（输入、环境、版本、频率）。无法复现就先列出缺的信息，不要开始猜。
2. **缩小**：按「最近改动 / 数据 / 环境 / 并发 / 外部依赖」二分，每一步都要能排除一半可能。
3. **假设**：给 1–3 个候选原因，每个都写清「如果成立，应该观察到什么」。
4. **验证**：优先加日志、断言、最小复现用例；不做与定位无关的重构。
5. **修复**：只改与根因相关的代码，并说明为什么这样改能消除现象。
6. **复验**：给出可执行的检查（命令、用例、观察点），而不是「应该好了」。

## 输出

1. 现象（一句话）
2. 根因，或「当前最可能 + 还缺哪条证据」
3. 最小修复
4. 复验方式

## 禁止

- 一次抛出多个互斥原因却不验证
- 用「可能是缓存 / 网络问题」当结论
- 没有证据就大面积改代码
