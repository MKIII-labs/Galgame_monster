# 先读后改

在动手之前先把「要改的东西」和「谁在用它」读清楚，避免凭文件名或记忆猜结构。

## 何时用

- 要改一个还没读过的文件、函数或配置
- 不确定改动会波及哪些调用点 / 数据 / 序列化格式
- 准备凭文件名、目录名或上一轮的记忆直接写代码

## 核心步骤

1. **定位**：先读目标文件；用 search_files / search_code 找调用点、同名定义和测试。
2. **确认契约**：输入输出、错误处理、空值、数据格式、谁在调用。
3. **写改动计划**：一次只改一类（行为 / 重命名 / 搬文件），列出会被影响的文件。
4. **动手**：只改已经确认的位置；遇到不确定的地方继续读，不要猜。
5. **回读**：改完再看一遍 diff，确认没有顺手改无关代码、没有留下半截。

## 输出格式

- 读了哪些文件（路径）
- 改了什么、为什么
- 还没确认的部分（如果有）

## 常见错误

- 凭文件名猜目录结构
- 只看定义、不看调用点
- 改一处顺便重构另一处
- 没读测试就修改实现
- 没读配置就假设默认值
