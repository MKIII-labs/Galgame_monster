# 验证先行

让「改好了」有证据，而不是一句断言。**改过文件就必须验证；没跑过验证不要说完成。**

## 何时用

- 改代码、改配置、修 bug 之后
- 用户问「确认一下」「真的好了吗」
- 需要判断改动有没有引入回归

## 核心步骤

1. 先写验收点：每条对应一个可观察结果（命令退出码、页面行为、文件内容）
2. 选最小验证：一条命令能证明就不跑全量；影响面大时才跑全量
3. 执行并保留原始输出：命令、退出码、关键行
4. 失败就回到根因，**不要修改测试或断言来迁就实现**
5. 报告时分清：通过 / 失败 / 没有覆盖到的部分

## 输出格式

- 验收点 → 验证方式 → 结果（附证据）
- 未覆盖的部分与原因

## 常见错误

- 用「应该可以」代替运行结果
- 只跑测试，不检查断言是否真的覆盖了改动
- 失败后悄悄删掉、跳过或放宽测试
- 只验证成功路径，不验证错误路径
- 改了文件但一条命令都没跑，就说「完成」
