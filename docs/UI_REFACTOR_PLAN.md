# Galgame_monster 界面系统性重构方案

> 状态：**已确认，进入实施**（2026-11-13）
> 备份提交：`509ab39 chore: 重构前备份现有界面与代码状态`
> 适用范围：`web/` 下的经典界面（HTML / CSS / 原生 JS）+ Electron 窗口壳；不改后端 API、数据格式与功能语义。
> 目标：在不删减任何现有功能的前提下，降低操作步骤与认知负担，建立清晰的信息层级和统一的视觉规范。
> 已确认决策：4 工作区固定导航 + 检查器；设置全屏保留 14 页；新增命令面板 / 检查器 / 待发送托盘三项；
> **IDE 允许深度重做布局与面板交互**（Monaco / xterm / Git / 调试内核仍复用现有实现）。

---

## 0. 一页结论

- **保留**：现有 4 个工作区（Solo / IDE / 大厅 / 工作台）、插件、阅读器、分享、14 个设置页签、6 个大厅模块、全部对话与工具能力。
- **重做**：全局壳层、导航层级、对话工作区、设置信息架构、大厅模块外壳、工作台布局、视觉令牌与组件规范、移动端交互。
- **不做**：不换框架、不引入前端构建链、不改 API 协议、不改会话 / 配置 / 数据文件结构；IDE 允许重排布局与面板交互，但不替换 Monaco / xterm 内核，也不重写 Git / 调试 / LSP 的业务逻辑。
- **唯一新增功能**：全局命令面板（Ctrl/⌘ K）。其余都是“合并入口 / 调整层级 / 统一视觉”，不新增业务能力。
- **实施**：P0 基线 → P1 壳层与设置 → P2 对话 → P3 大厅与工作台 → P4 IDE / 阅读器 / 移动端 → P5 无障碍 / 性能 / 兼容性验收。每阶段独立提交、独立回退。

- ≤900px 侧栏变覆盖式抽屉；≤640px 弹窗全屏、设置导航变顶部横条。**没有移动端底部导航，也没有 `env(safe-area-inset)`。**

## 7. 问题清单（按优先级）

### P0（直接影响效率与理解）

1. **常驻控件过多**：输入区 6 个按钮 + 3 个能力胶囊 + 3 个下拉；侧栏底部 8 个同权重按钮。
2. **状态分散**：同一件事（正在生成 / 待处理 / 连接异常）在多个位置重复表达，用户不知道看哪里。
3. **弹窗碎片化**：上下文、用量、轨迹、存档、知识库、笔记各占一个 modal；查看统计必须打断对话。
4. **设置信息架构过重**：14 页签、Agent 页 20+ 卡片、术语密集；保存语义混杂（草稿保存 / 即时保存 / 独立保存）。
5. **视觉层级平**：高频与低频操作同权重；主次按钮、危险操作、导航与工具没有明确分层。

### P1（影响一致性与移动端）

6. **入口重复 / 缺失**：模式切换 4 套入口；插件不在主切换条；阅读器只能从 IDE 的 PDF 进入。
7. **组件不统一**：按钮高度、卡片圆角、弹窗宽度、z-index 各模块各写一套。
8. **移动端弱**：无底部导航、无安全区、会话操作只能 hover、IDE 只能横滚。
9. **无障碍缺口**：对话框语义、焦点陷阱、图标名称、减少动效覆盖不足。

### P2（可维护性与细节）

10. 术语难懂：`modsearch`、`quality / balanced`、`worktree`、`fidelity` 等需要查帮助。
11. 硬编码颜色约 120 处，主题扩展与对比度校验困难。
12. 隐藏的 GAL 页与残留 DOM / CSS / JS 增加维护噪音（入口已下线）。

## 8. 高风险语义（重构中不得改变）

以下配置或字段会直接影响后端行为 / 用户数据，重构只改展示与入口，不改语义：

- 上下文与输出：`chat_context_limit`、`chat_reserve_output`、`chat_max_tokens`，以及 `0` 的“不限 / 自动 / 服务商默认”含义。
- 视觉与搜索：`vision_prefer_api`、`chat_kind` 自动判定、`search_modsearch_enabled` 与免注册引擎链。
- 提醒：4 个提醒开关即时写盘并同步 Windows 计划任务。
- 画像：`profile.rules` 顺序 / 启用状态、`learning_prompt_custom` 占位符。
- 子代理 / Skill：文件路径、`permission: write`、内置删除后可恢复。
- 隔离与审批：`agent_write_isolation`、`agent_worktree_isolation`、`agent_fidelity_*`、审批预设写入 `data/agent-rules.json`。
- 重置：必须保留 API Key、B 站 SESSDATA、自定义预设。
- 备份：必须继续排除 API Key。
- 会话字段：`agent_enabled`、`sandbox`、`approval_mode`、`kb_ids`、`use_memory`、`use_profile`。
- `chat_fallback`（当前无 UI，只存在于配置）不得丢弃或覆盖。

# 第二部分：重构整体方案

## 9. 设计原则与目标

1. **任务优先，模式靠后**：用户是来“对话 / 改代码 / 练一次 / 看数据”的，不是来“进入某个模式”。工作区仍保留，但入口收敛为一个导航栏。
2. **渐进披露**：常驻控件只保留高频 4 个；能力开关收进一个“能力”浮层，激活后以芯片形式回显。
3. **单一状态源**：生成状态、队列、连接、上下文占用统一到一条状态带 + 一个检查器，不再到处放圆点和横幅。
4. **视觉分层**：三层表面、两级边框、三级文字；一屏最多一个主按钮、两个强调色区域。
5. **内核保守**：API、数据、配置语义、Monaco / 终端内核不动；优先 CSS 与 DOM 包装，函数名与 id 尽量不改。
6. **可验证**：每个阶段都有功能清单、回归命令与验收门；任何阶段可单独 revert。

├──────┬───────────────────────────────────────────┬───────────────┤
│ 导航  │ 上下文侧栏 240                            │ 检查器 320     │

| 大厅 | 功能大厅 | 6 个模块导航 | 首页卡片墙 + 模块内页 |

## 11. 布局调整详细规划

### 11.1 全局壳层

- **左侧导航栏**：宽 56/64px，仅图标 + 悬浮标签；当前项用左侧 2px 强调条 + 浅强调底。
- **上下文侧栏**：宽 240px，可折叠为 0；会话 / 文件树 / 模块列表按当前工作区切换。
- **顶栏**：48px，左侧工作区标题 + 面包屑，中间命令入口，右侧模型状态、连接状态、检查器开关。
- **检查器**：宽 320px，≥1440px 常驻可收起；901–1439px 覆盖式；≤900px 底部抽屉。
- **主区**：最大内容宽 1120px（对话 / 设置），IDE 与大厅占满；统一 16px 外边距。

### 11.2 对话工作区

```
┌ 会话标题 · 状态 · 新对话 / 搜索 / 更多 ────────────────┐
│ 消息流                                                  │
│  用户消息：正文 + 附件缩略图                             │
│  助手消息：答案优先                                       │
│    └ 过程（思考 2 · 工具 5 · 计划 3/4）  默认折叠         │
│    └ 结束操作：继续 / 重试 / 重新生成 / 编辑              │
│ 待发送托盘：附件 / 引用 / 排队                             │
│ 状态带：上下文 42% · 已连接 · 队列 1                      │
│ 输入区：文本域                                           │
│         [附件] [语音] [能力 ▾]            [发送 / 停止]  │
└─────────────────────────────────────────────────────────┘
```

- **消息层级**：答案永远优先；思考、工具、计划、子代理、探索、验收、工作流统一进一个“过程”折叠区，运行中默认展开当前步骤，结束后自动收起并显示统计。
- **结束操作内联**：继续 / 重试 / 重新生成 / 编辑放在消息末尾的操作条，不再散落在横幅或提示里。
- **状态带**：位于消息流与输入区之间，一行展示连接、流式、队列、上下文占用；点击上下文数字打开检查器。
- **输入区**：常驻 4 个控件（附件、语音、能力、发送 / 停止）；“能力”浮层内放思考、联网、Agent、沙箱、审批模式、续跑；激活后在输入区显示最多 3 个可关闭芯片。
- **待发送托盘**：附件、引用、`#` 上下文引用、队列统一成一条可横向滚动的芯片带，支持一键清空。
- **侧栏会话行**：标题、时间、状态点；操作收进“⋯”菜单，触屏常显；保留分组、置顶、拖拽、Alt+↑↓、搜索。

### 11.3 设置

- **全屏设置层**，不再是 720–900px 的居中 modal。
- 左侧 240px 导航：搜索框 + 4 组 14 页签；支持“常用”置顶。
- 右侧内容最大 880px，卡片式分区；顶部页标题 + 说明，底部 sticky 保存栏。
- 保留：14 页、页内锚点、搜索、草稿、脏提示、`Ctrl+S`、取消、本页恢复默认、全量重置。

## 17. 质量验收标准

### 17.1 功能完整性

- 第 14 节清单 100% 通过；不删功能、不改 API、不改数据格式。
- 现有 pytest 与前端测试全通过；新增 UI 冒烟测试覆盖关键路径。
- 设置保存 / 取消 / 恢复默认 / 重置语义与现状一致；密钥、SESSDATA、预设不被重置或备份。

### 17.2 性能

- 首屏引用 JS/CSS 数量 ≤ 89，gzip 总体积 ≤ 1,042 KB（目标下降 10%）。
- FCP / LCP / TBT / CLS 相对 P0 基线不退化超过 5%；无新增 >200ms 长任务。
- 不新增第三方运行时依赖；Monaco / xterm / KaTeX 仍按需加载。

### 17.3 兼容性

- Windows 10/11 + Edge / Chrome（Chromium 111+）；Electron 窗口壳。
- 360 / 768 / 1024 / 1440 / 1920 五档无意外横向溢出；触屏操作可用。
- 保留 `color-mix()` / `dvh` / `:focus-visible` 的现有能力检测与降级策略。

### 17.4 无障碍

- WCAG 2.1 AA 基础项：焦点可见、键盘可达、对话框 `role/aria-modal` + 焦点陷阱、图标名称、表单标签、正文对比度 ≥ 4.5:1。
- `prefers-reduced-motion` 覆盖所有过渡与动画。
- 触控目标 ≥ 40×40（关键操作 44×44）。

### 17.5 稳定性

- 所有原有功能的操作流程可用；不要求步骤完全相同，但不得出现无法完成的操作。
- 会话 / 配置 / 知识库 / 存档 / 备份数据零迁移、零丢失。

## 18. 风险与回滚

| 风险 | 对策 |
|---|---|
| 原生 JS 全局耦合，改名导致隐性断链 | 不改函数名 / id；优先 CSS + DOM 包装；每阶段跑功能勾表 |
| IDE 深度重做导致 Monaco / 终端 / Git 回归 | 先包容器再逐面板迁移；每个面板迁移后跑 IDE 回归清单；保留旧入口直到新入口验证通过 |
| 弹窗合并进检查器后找不到功能 | 保留旧函数入口作为兼容包装，确认无遗漏后再移除旧 UI |
| 设置保存语义被改坏 | 保留 `collectSettings` / 草稿 / 增量保存逻辑，只改布局 |
| 视觉改动导致低对比度 | 令牌 + 对比度检查 + 截图比对 |
| 移动端布局回归 | 五档视口自动截图 + 横向溢出检查 |
| 性能下降 | P0 基线 + 每阶段复测 + 体积预算 |
| 需要整体回退 | 备份提交 `509ab39`；每阶段独立提交；`git revert` 单阶段 |
